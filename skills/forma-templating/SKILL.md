# forma-templating — шаблон проекта из текущего проекта

Шаблон = маршрут + базовые цели девяти видов в общем виде + обезличенные скиллы. Образец формы — `templates/forma-wordpress-novamira/` в каталоге плагина `forma`.

## Что входит / не входит

| Входит | Не входит никогда |
|---|---|
| `project/ROUTE.md` — маршрут (шаги, вход/выход, почему такой порядок); `project/brief/idea.md` — только каркас разделов, содержание обезличено до пометок «ещё не спрошено» | карточки `.devtool/features/`, `project/cards/` |
| базовые цели девяти видов (`value`, `docs`, `forma`, `result-image`, `core`, `incoming`, `goal`, `experience`, `review-image`) — порядок, образ результата и признак **в общем виде**, как алгоритм | история, расход, `JOURNAL.md`, `dashboard/*.log` |
| подцели `goal-NN` — только как обобщённый порядок шагов, без предмета проекта | `VARS/`, `.env`, `project/brief/` (кроме каркаса `idea.md`) |
| скиллы проекта, очищенные от привязки (`.claude/skills/*`, кроме скиллов ядра `forma`) | `project/experience/`, `project/CONFIG.md`, `mockups/`, `reference/` |

Реестр видов — `intent-goal-opening.md`, «Epic». Цели — `project/goals/`, форма целого — `project/ROADMAP.md`.

## Шаги

1. **Имя.** Спросить у человека. Не придумывать.
2. **Уникальность.** Имя не должно совпадать с `name` в `.claude-plugin/marketplace.json` каталога `forma` и с именами из `claude plugin list`. Совпало — сказать, с чем, и спросить новое. Формат: `kebab-case`, латиница.
3. **Инвентарь.** Показать человеку, что пойдёт в шаблон: `ROUTE.md`, каркас `idea.md`, девять базовых целей, список подцелей, список скиллов-кандидатов. Человек вычёркивает лишнее.
4. **Список обезличивания** — собрать и показать **до упаковки**, таблицей `что было → чем заменяется`:
   - название проекта/сайта, домен(ы), бренд;
   - имена и логины из `VARS/test-users.md`, `VARS/credentials.md` (только имена-ключи, значения не читать в вывод);
   - id постов/шаблонов/снипетов, пути сервера, URL;
   - предметные сущности (категории, разделы) → роль в общем виде («сущность каталога», «раздел N»).
   Замена — плейсхолдер `{{PROJECT_NAME}}`, `{{DOMAIN}}` и т.п. либо общее слово. **Упаковывать только после явного «да» человека на этот список.** Правки человека — внести, показать снова.
5. **Упаковка** в `<каталог forma>/templates/<имя>/`:
   - `.claude-plugin/plugin.json` — `name`, `displayName`, `description`, `version: "0.0.1"`, `license: "MIT"`;
   - `README.md` — что внутри, установка (`claude plugin install <имя>@forma`), статус маршрута (пройден системой или проекция практики — как в исходном `ROUTE.md`);
   - `skills/<имя>/SKILL.md` — установщик: кладёт в проект `project/ROUTE.md`, `project/brief/idea.md` (если есть) и `project/goals/goal-<код>/GOAL.md` девяти видов (+ обобщённые подцели) из `skills/<имя>/template/`; не перезаписывает существующее молча;
   - `skills/<скилл>/` — обезличенные скиллы проекта;
   - запись в `.claude-plugin/marketplace.json`: `{"name": "<имя>", "source": "./templates/<имя>", "description": "..."}`.
6. **Проверка утечек** — по упакованной папке, до отчёта:
   ```
   grep -rniE "<название>|<домен>|<имя1>|<имя2>|..." templates/<имя>/
   ```
   Термины — ровно из утверждённого списка шага 4. Вывод должен быть пуст. Не пуст — исправить, повторить.
7. **Пробная установка** в пустую временную папку (вне репозитория): развернуть шаблон его же установщиком (или скопировать `template/` как это сделает установщик), повторить grep шага 6 по результату. `claude plugin validate <путь>` — если команда есть в версии CLI.
8. **Версия** `plugin.json` ядра `forma` — patch-шаг, как принято в проекте. Не пушить — только по команде человека.
9. Отчёт человеку: путь, состав, результат grep (пусто), что осталось за ним (публикация, установка у себя).
