# Spend line — Claude Code

Read this file when you write a spend line into a card's `## History`: `Intent` after a node returns and before a card's commit; `Kit` or `Run` after an external-model call they made themselves. The contract itself — skeleton, fields, the `unknown` state, external model and service, `Intent`'s own lines — `.forma/manual/en/03-forma/ECONOMY.md`; the law — `AGENTS.md` §3. This file holds what is true of Claude Code alone: which field of a return fills which variable, and which scripts do the reading.

* **Spend fields (§3):** the call's own result carries `<usage>` with exactly three fields — tokens in `subagent_tokens`, tool reaches in `tool_uses`, duration in `duration_ms` (milliseconds; the contract wants whole seconds). The call id the law asks for is `agent_id`, in the same return. **Cache-read is not among them and never has been:** `<usage>` does not carry `cache_read_input_tokens`, so R is read from the call's own transcript — `node .forma/dashboard/subagent-transcript.cjs <agent_id>` — which is a reading of the same call, not a second call. The caller reads all of it from the call itself, never by estimate. Mapping to the economy contract (`.forma/manual/en/03-forma/ECONOMY.md`): `subagent_tokens` → N, transcript `cache_read_input_tokens` → `cache_read`, `duration_ms`/1000 → `duration_s`, `agent_id` → `call_id`, `tool_uses` → `tool_uses`; transcript `input_tokens`/`output_tokens`/`cache_creation_input_tokens` → `tokens_in`/`tokens_out`/`cache_write` (adapter `claudeUsage` in `session-economy.cjs`, `card-session-spend.cjs`). Engine tag: `claude-code:`.
* **Economy adapter (`.forma/manual/en/03-forma/ECONOMY.md`):** `.claude/scripts/claude-economy.cjs` is the one place Claude field names become canonical variables; `subagent-transcript.cjs`, `card-session-spend.cjs`, `session-economy.cjs` read through it, `.forma/dashboard/spend-line.cjs` (`formatSpendLine`) writes the line. A field the source lacks is `unknown`, never 0 (`claude-economy.test.cjs`). Spend line of a subagent call: `node .claude/scripts/claude-economy.cjs line --node <Node> --agent-id <agent_id> --tokens <subagent_tokens> --duration-ms <duration_ms> [--tool-uses <n>] --desc "<what>"`.

  | Variable | Subagent call | Main session (`Intent`) |
  |---|---|---|
  | `tokens` (N) | `<usage>` `subagent_tokens` | Σ `tokens_in + cache_write + cache_read + tokens_out` over the card's answers |
  | `cache_read` (R) | transcript `agent-<agent_id>.jsonl`, Σ `cache_read_input_tokens`; no transcript — `unknown` | transcript, Σ `cache_read_input_tokens` |
  | `cache_write` | transcript, Σ `cache_creation_input_tokens`; absent from `<usage>` — `unknown` | transcript, same field |
  | `tokens_in` / `tokens_out` | transcript `input_tokens` / `output_tokens`; absent from `<usage>` — `unknown` | transcript, same fields |
  | `duration_s` (T) | `<usage>` `duration_ms` / 1000, rounded | active time between entries, gaps cut at `--idle` |
  | `call_id` | `agent_id` of the return | session id (transcript file name) |
  | `tool_uses` | `<usage>` `tool_uses` | not counted |

  Transcript steps are deduplicated by `requestId` (subagent) / `message.id` (main session).
* **`Intent` spend per card (`ECONOMY.md`, "`Intent` in the shared session"):** `node .claude/scripts/card-session-spend.cjs <NNN> --write` — before the card's commit; engine tag `claude-code:`. Reads the same main-session transcripts, splits them by card (each answer goes to the card whose file or commit follows it), subagent answers excluded.
* **Dialog spend (`ECONOMY.md`, "`Intent` in the shared session", the whole-dialog ledger):** `node .claude/scripts/session-economy.cjs --session current` — main-session transcripts `~/.claude/projects/<project>/*.jsonl` touched in the last 30 min (subagent transcripts sit in `<session>/subagents/` and are not read); the full ledger — the same script without the flag. Shown on the dashboard's main tab beside the five nodes.
* **Continuation line (`AGENTS.md` §2, `kit.md` "Return"):** a `SendMessage` to a live call's `agent_id` returns `<usage>` the same shape as a fresh `Agent` call — same fields, same reading. `Kit` writes the line the same way as any other attempt, same `agent_id`, with `continuation` named in the description so the ledger can tell it apart from a reassembly: `` `Kit`, YYYY-MM-DD: attempt (continuation), N tokens (R cache-read), T s, `<agent_id>` — claude-code: <correction sent, one sentence>. `` The repeated `agent_id` across two lines of the same card is expected — it is what marks the pair as one call continued, not two.
