# `Spec` — Unattainable value

Read this file when `Kit` has escalated that a value recorded in `VARS/` is unattainable in the environment. Shared rules — `.claude/agents/spec.md`.

## Unattainable value

`Kit` escalated: the environment won't give what's recorded in `VARS/`. What lands on your desk has already been through `Kit`'s first read of the same table (`kit-limits.md`, "Environment limitation"); yours is the second, colder read — is this really unaffordable for the whole project, or was the card simply specified badly for the one page it hit:

| What | Cost | Where |
|---|---|---|
| local workaround: this detail on this page is different, it doesn't surface elsewhere | one attempt | `Kit`, normal order |
| **unattainable value**: affects everyone who relies on it | the whole project | `Spec` → **human, stop** |

Don't rewrite the card and don't swap the value. **Stop and report to the human**: which value, how the environment limits it, what values are available, what relies on this one. A value holds what's already been built; changing it on the fly means what's built drifts from what gets built next, and the drift stays invisible.
