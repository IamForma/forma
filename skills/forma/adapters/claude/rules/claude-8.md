# 8. Engine architecture in Claude Code

The protocol itself is `AGENTS.md`, read natively by Claude Code when no `CLAUDE.md` sits in the working directory or above it — sections 1–7, identical in every environment. This file adds only what is true of Claude Code and of no other engine. Nothing here overrides a rule above; it says where that rule's machinery lives.

* **Root rules:** `AGENTS.md`. This file carries no copy of them — one source, never two. Editing the protocol means editing `AGENTS.md`; editing this file means changing something about Claude Code alone. Housekeeping of both, and how they are verified — `intent-housekeeping.md`.
* **Agent definitions:** `.claude/agents/*.md` and `.claude/agents/on-demand/*.md` — this is the "role directory" that sections 1–7 refer to by bare filename (`kit.md`, `spec.md`, `intent-goal-opening.md` and so on). **Run's own catalog:** `.claude/agents/run/*.md` — one profile per `Run` subject (`run-site-build`, `run-site-php`, `run-image`, `run-text`, `run-mechanical`, `run-visual-check`); `run.md` stays the base template, not a role. `Kit` picks the profile by the task's subject — `kit.md`, "Task kitting".
* **Execution:** Subagents are invoked via Claude Code's native `Agent` tool (`subagent_type`).
* **Continuation of the same `Run` (§2, "no direct return to `Run`, exception"):** the mechanism is `SendMessage`, addressed to the live call's own id (the same `agent_id` a spend line reads, `spend-line.md`). `Kit` sends the written correction there instead of opening a new `Agent` call. Two hard gates, checked before anything else: no `agent_id` recorded for that attempt, or the call has already returned/closed — either one means `SendMessage` has nothing to address, and the choice is B (reassemble, new `Agent` call), never a retry of A. The correction travels as plain text to that id; nothing else about the call (its tools, its role, its model) changes underneath it — a change there is a kit change and forces B, per `kit.md`.
* **Spend line (§3):** field mapping (`<usage>`, the call's transcript), the scripts `claude-economy.cjs line` and `card-session-spend.cjs`, the dialog ledger — `.claude/agents/on-demand/spend-line.md`; read it when you write a spend line. Engine tag: `claude-code:`.
* **MCP configuration:** `.claude/.mcp.json` and `.mcp.json`.
* **Hooks:** `.claude/settings.json` with `.claude/hooks/guard-delete.sh` (the delete-guard of §2), `check-ready.sh`, and `.claude/hooks/check-card.sh` (`PostToolUse`: the core board check, `.forma/board/check-board.cjs <card>`, on every write into `.devtool/features/`; reports a broken card at the moment of writing).
* **Main session = `Intent` (§1):** the main Claude Code session is `Intent`. The `SessionStart` hook `.claude/hooks/intent-start.sh` delivers `.claude/agents/intent.md` and `.claude/agents/on-demand/intent-session-start.md` into its context and shows the human the dashboard link (`systemMessage`). Cards are created with `node .forma/board/new-card.cjs` (core).
* **Zone of edits:** Claude Code edits its own files (`.claude/`) and the shared `AGENTS.md`; `.codex/` is Codex's, `.agents/` and `GEMINI.md` are Gemini's — a divergence there is named to the human as a fact, never fixed by hand (full rule, and the commit check against the full cross-engine check — `intent-housekeeping.md`).

**Delivery.** Claude Code reads `AGENTS.md` (§1–7) and this file itself: with no `CLAUDE.md` in the root, both arrive as project instructions; a root `CLAUDE.md` would shadow that reading, and `sync-engines --check` reports it as a breach. Where native reading fails (older than v2.1.277, Bedrock, telemetry disabled), register the fallback `.claude/hooks/load-engine-section.sh` (`startup|resume|clear`) in `.claude/settings.json`; registered while native reading works, it delivers §8 twice.
