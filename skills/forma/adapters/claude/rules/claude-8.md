# 8. Engine architecture in Claude Code

The protocol itself is `AGENTS.md`, read natively by Claude Code when no `CLAUDE.md` sits in the working directory or above it — sections 1–7, identical in every environment. This file adds only what is true of Claude Code and of no other engine. Nothing here overrides a rule above; it says where that rule's machinery lives.

* **Root rules:** `AGENTS.md`. This file carries no copy of them — one source, never two. Editing the protocol means editing `AGENTS.md`; editing this file means changing something about Claude Code alone. Housekeeping of both, and how they are verified — `intent-housekeeping.md`.
* **Agent definitions:** `.claude/agents/*.md` and `.claude/agents/on-demand/*.md` — this is the "role directory" that sections 1–7 refer to by bare filename (`kit.md`, `spec.md`, `intent-goal-opening.md` and so on). **Run's own catalog:** `.claude/agents/run/*.md` — one profile per `Run` subject (`run-site-build`, `run-site-php`, `run-image`, `run-text`, `run-mechanical`, `run-script`, `run-python`, `run-visual-check`); profiles of one product live in the project's own `project/extensions/claude/agents/run/` (copied into `.claude/agents/run/` by `.forma/extensions/extensions.cjs`) and are listed in `PROJECT.md`, never here; `run.md` stays the base template, not a role. `Kit` picks the profile by the task's subject — `kit.md`, "Task kitting".
* **Execution:** Subagents are invoked via Claude Code's native `Agent` tool (`subagent_type`) — held only by the main session (`Intent`). A subagent has no `Agent` tool of its own and cannot invoke another subagent: `Kit`'s own tool list (`kit.md` frontmatter) carries no `Agent`. `Kit` assembles the six units and returns the finished kit to its caller, the main session; the main session is the one that calls `Run` via `Agent`. Exception: the short route, the card's label `route-4` (`AGENTS.md` §7) — there `Kit` executes the task itself and never hands off to `Run`.
* **Continuation of the same `Run` (§2, "no direct return to `Run`, exception"):** the mechanism is `SendMessage`, addressed to the live call's own id (the same `agent_id` a spend line reads, `spend-line.md`) — held, like `Agent`, only by the main session. `Kit` writes the correction and hands it to the main session, which sends it via `SendMessage` instead of opening a new `Agent` call; `Kit` itself never calls `SendMessage` or `Agent`. Two hard gates, checked before anything else: no `agent_id` recorded for that attempt, or the call has already returned/closed — either one means `SendMessage` has nothing to address, and the choice is B (reassemble, the main session opens a new `Agent` call), never a retry of A. The correction travels as plain text to that id; nothing else about the call (its tools, its role, its model) changes underneath it — a change there is a kit change and forces B, per `kit.md`.
* **The Plumb (§2, "The Plumb"):** its built-in executor is the subagent `plumb-haiku` (`.claude/agents/plumb-haiku.md`: `claude-haiku-5-5`, `omitClaudeMd`, tool `Read` only), invoked via `Agent` — held only by the main session, since `Spec` is itself a subagent and has no `Agent` tool. The main session therefore runs the Plumb for `Spec`: `Spec` returns the sliced cards, for `plumb-haiku` the main session scrubs (`node .claude/scripts/plumb-scrub.cjs <card>`), calls the executor and hands the reading back to `Spec` to decide and write; for `jev` the driver scrubs itself (next item). The external executor is called, on the scrubbed text only, by `.claude/scripts/external-model-bridge.cjs` over HTTPS with the key from `.env` (never from the shell); `plumb-scrub.cjs` only scrubs. The setting `plumb: haiku | jev` and the thresholds live in `project/config/PROJECT.md`, «Маршруты». The Plumb line is written by `Spec` once it has the reading of `plumb-haiku`; for `jev` the driver writes it (next item).
* **`jev`:** when `plumb: jev`, the main session runs `node .forma/plumb/plumb-run.cjs <card> --write` instead of the `Agent` call to `plumb-haiku`. The driver scrubs the task and the role catalog itself (reuses `plumb-scrub.cjs`'s functions), then calls the OpenRouter Decisions API (`typesafe/jev-1.14`, `POST /api/alpha/decisions`, a typed `questions`+`state` request, not `chat/completions`) through `external-model-bridge.cjs` (`callDecisions`, price in `PRICING.openrouter['typesafe/jev-1.14']`) and prints `{choice, score, noul, meta}` — the same shape `plumb-haiku` returns, plus `meta` for the spend line; `--write` also appends the one Plumb line (role, probability, gap, clarity, executor, outcome by the `PROJECT.md` thresholds, spend in its own unit) to the card's `## History` in the same call. On a missing `OPENROUTER_API_KEY`, a bridge error or a scrub refusal it prints `{"fallback":"haiku","reason":...}` and exits 0 — it never calls `Agent` itself (it has none); no line is written then; the main session reads the fallback, calls `plumb-haiku` instead (with its scrub step), and `Spec` records that attempt as `haiku`, the reason named. The one-time switch, `node .claude/scripts/plumb-switch.cjs`, flips only the `plumb` selector word in `PROJECT.md`; it stops without writing anything when the key is absent, and never sets a call limit or jev-specific thresholds — the human sets both (`AGENTS.md` §3).
* **Automatic recording (§3, `ECONOMY.md`, "Automatic recording"):** the `SubagentStop` hook in `.claude/settings.json` runs `.claude/scripts/ledger-recorder.cjs` on every subagent return: a record in `.claude/.ledger/calls.jsonl` (the file `ledger-parity.cjs` reads) and a spend line in the `## History` of each card named in the call's prompt, deduplicated by `agent_id`; errors never block (`.claude/.ledger/errors.log`). The manual commands of `spend-line.md` are the fallback — only when the hook is absent or the line did not appear.
* **`Intent` spend by hook:** the `SessionEnd` hook runs `.claude/scripts/card-session-spend.cjs --auto` — a line per card the session touched, for answers not yet counted (window boundary dedup, shared with `card-move.cjs --session-spend`); errors never block. The manual command is the fallback.
* **Spend line (§3):** field mapping (`<usage>`, the call's transcript), the scripts `claude-economy.cjs line` and `card-session-spend.cjs`, the dialog ledger — `.claude/agents/on-demand/spend-line.md`; read it when you write a spend line. Engine tag: `claude-code:`.
* **MCP configuration:** `.claude/.mcp.json` and `.mcp.json`.
* **Access levels:** `малый` / `средний` / `сайт` / `полный` (`minimal` / `standard` / `site` / `full`) — presets of tool permissions, described in `.claude/permission-levels.json`, applied by `node .claude/scripts/permissions-level.cjs <level>` into `.claude/settings.local.json` (the human's file: only the script's own entries are written and removed; its record, `.claude/permission-level.state.json`, stays out of git). `Intent` runs it on the human's word (`intent.md`, «Every request», item 7). The project's default level is set in `PROJECT.md`; no level is applied on its own. Engine-specific: `.codex/` and `.agents/` have their own permission models.
* **Hooks:** `.claude/settings.json` with `.claude/hooks/guard-delete.sh` (the delete-guard of §2), `check-ready.sh`, and `.claude/hooks/check-card.sh` (`PostToolUse`: the core board check, `.forma/board/check-board.cjs <card>`, on every write into `.devtool/features/`; reports a broken card at the moment of writing).
* **Main session = `Intent` (§1):** the main Claude Code session is `Intent`. The `SessionStart` hook `.claude/hooks/intent-start.sh` delivers `.claude/agents/intent.md` and `.claude/agents/on-demand/intent-session-start.md` into its context and shows the human the dashboard link (`systemMessage`). Cards are created with `node .forma/board/new-card.cjs` (core).
* **Zone of edits:** Claude Code edits its own files (`.claude/`) and the shared `AGENTS.md`; `.codex/` is Codex's, `.agents/` and `GEMINI.md` are Gemini's — a divergence there is named to the human as a fact, never fixed by hand (full rule, and the commit check against the full cross-engine check — `intent-housekeeping.md`).

**Delivery.** Claude Code reads `AGENTS.md` (§1–7) and this file itself: with no `CLAUDE.md` in the root, both arrive as project instructions; a root `CLAUDE.md` would shadow that reading, and `sync-engines --check` reports it as a breach. Where native reading fails (older than v2.1.277, Bedrock, telemetry disabled), register the fallback `.claude/hooks/load-engine-section.sh` (`startup|resume|clear`) in `.claude/settings.json`; registered while native reading works, it delivers §8 twice.
