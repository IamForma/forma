# Spend line — Claude Code

**Write the line exactly to `AGENTS.md` §3's template, every field present in order — `attempt,` as its own word, never a bare number in its place; the dash before the engine tag.** A line that drops a word or reshapes the punctuation still reads to a human, but `tally.cjs` and `check-board.cjs` parse it by that exact shape — a malformed line is invisible to both and the card can reach `done` without either ever having checked it. Prefer the script's own output (below) over hand-typing the line; if you do type it, check it against the template before you write it, not after.

Read this file when you write a spend line into a card's `## History`: `Intent` after a node returns and before a card's commit; `Kit` or `Run` after an external-model call they made themselves. The contract itself — skeleton, fields, the `unknown` state, external model and service, `Intent`'s own lines — `.forma/manual/en/03-protocol/ECONOMY.md`; the law — `AGENTS.md` §3. This file holds what is true of Claude Code alone: which field of a return fills which variable, and which scripts do the reading.

* **Spend fields (§3):** the call's own result carries `<usage>` with exactly three fields — tokens in `subagent_tokens`, tool reaches in `tool_uses`, duration in `duration_ms` (milliseconds; the contract wants whole seconds). The call id the law asks for is `agent_id`, in the same return. **Cache-read is not among them and never has been:** `<usage>` does not carry `cache_read_input_tokens`, so R is read from the call's own transcript — `node .forma/dashboard/subagent-transcript.cjs <agent_id>` — which is a reading of the same call, not a second call. The caller reads all of it from the call itself, never by estimate. **`subagent_tokens` is not spend:** measured against transcripts it equals the context size at the call's last step, 10–40× below the contract's N. N is Σ `tokens_in + cache_write + cache_read + tokens_out` over the transcript's steps (deduplicated by `requestId`); `claude-economy.cjs line` takes it from the transcript and uses `--tokens` only when no transcript exists, marking it in the description as context size. Mapping to the economy contract (`.forma/manual/en/03-protocol/ECONOMY.md`): transcript Σ (above) → N, transcript `cache_read_input_tokens` → `cache_read`, `duration_ms`/1000 → `duration_s`, `agent_id` → `call_id`, `tool_uses` → `tool_uses`; transcript `input_tokens`/`output_tokens`/`cache_creation_input_tokens` → `tokens_in`/`tokens_out`/`cache_write` (adapter `claudeUsage` in `session-economy.cjs`, `card-session-spend.cjs`). Engine tag: `claude-code:`.
* **Economy adapter (`.forma/manual/en/03-protocol/ECONOMY.md`):** `.claude/scripts/claude-economy.cjs` is the one place Claude field names become canonical variables; `subagent-transcript.cjs`, `card-session-spend.cjs`, `session-economy.cjs` read through it, `.forma/dashboard/spend-line.cjs` (`formatSpendLine`) writes the line. A field the source lacks is `unknown`, never 0 (`claude-economy.test.cjs`). One call for the whole handoff (transcript read, line written, stage moved): `node .forma/board/card-move.cjs <card> --to <stage> --note "<what>" --agent-id <agent_id> --duration-ms <duration_ms> [--turns <tool_uses>]` — N, R and O come from the call's transcript; `--tokens <subagent_tokens>` is only the fallback and, when given, is written as is (context size, no transcript read); an id with no transcript gives `unknown tokens (cache-read unknown)` with the reason, never 0. Spend line alone, without a stage move: `node .claude/scripts/claude-economy.cjs line --node <Node> --agent-id <agent_id> --tokens <subagent_tokens> --duration-ms <duration_ms> [--tool-uses <n>] --desc "<what>"`.

  | Variable | Subagent call | Main session (`Intent`) |
  |---|---|---|
  | `tokens` (N) | transcript Σ `tokens_in + cache_write + cache_read + tokens_out`; no transcript — `<usage>` `subagent_tokens` (context size, marked) | Σ `tokens_in + cache_write + cache_read + tokens_out` over the card's answers |
  | `cache_read` (R) | transcript `agent-<agent_id>.jsonl`, Σ `cache_read_input_tokens`; no transcript — `unknown` | transcript, Σ `cache_read_input_tokens` |
  | `cache_write` | transcript, Σ `cache_creation_input_tokens`; absent from `<usage>` — `unknown` | transcript, same field |
  | `tokens_in` / `tokens_out` | transcript `input_tokens` / `output_tokens`; absent from `<usage>` — `unknown` | transcript, same fields |
  | `duration_s` (T) | `<usage>` `duration_ms` / 1000, rounded | active time between entries, gaps cut at `--idle` |
  | `call_id` | `agent_id` of the return | session id (transcript file name) |
  | `tool_uses` | `<usage>` `tool_uses` | not counted |

  Transcript steps are deduplicated by `requestId` (subagent) / `message.id` (main session).
* **`Intent` spend per card (`ECONOMY.md`, "`Intent` in the shared session"):** `node .claude/scripts/card-session-spend.cjs <NNN> --write` — before the card's commit; at the acceptance handoff the same line goes in the same call as the stage line: `node .forma/board/card-move.cjs <card> --to accept|close --note "<what>" --session-spend <NNN>` (the card's own number; the line is inserted before the stage line, written by the caller, nothing new is written when the journals hold no unaccounted answers; no touches in the journals stops the call before any write); engine tag `claude-code:`. Reads the same main-session transcripts, splits them by card (each answer goes to the card whose file or commit follows it), subagent answers excluded.
* **Dialog spend (`ECONOMY.md`, "`Intent` in the shared session", the whole-dialog ledger):** `node .claude/scripts/session-economy.cjs --session current` — main-session transcripts `~/.claude/projects/<project>/*.jsonl` touched in the last 30 min (subagent transcripts sit in `<session>/subagents/` and are not read); the full ledger — the same script without the flag. Shown on the dashboard's main tab beside the five nodes.
* **Splitting a batch call's spend (`ECONOMY.md`, "Splitting one call's spend across a batch"):** a `Spec` call slicing several cards, or a `Kit` call kitting up to 4, writes K lines from one call's `<usage>` — one per card touched, never the full total on each. `node .claude/scripts/claude-economy.cjs line --node <Node> --agent-id <agent_id> --tokens <subagent_tokens> --duration-ms <duration_ms> --split K --share I --desc "<what, for this card>"` divides N, R and T by K (exact integer split, remainder to the first shares) and appends `(batch I/K)` to the description — the marker `tally.cjs` reads to keep two equal shares from being mistaken for one line copied twice. `I` runs 1..K, one call per card in the batch, same `agent_id` throughout.
* **Continuation line (`AGENTS.md` §2, `kit.md` "Return"):** a `SendMessage` to a live call's `agent_id` returns `<usage>` the same shape as a fresh `Agent` call — same fields, same reading. `Kit` writes the line the same way as any other attempt, same `agent_id`, with `continuation` named in the description so the ledger can tell it apart from a reassembly: `` `Kit`, YYYY-MM-DD: attempt (continuation), N tokens (R cache-read), T s, `<agent_id>` — claude-code: <correction sent, one sentence>. `` The repeated `agent_id` across two lines of the same card is expected — it is what marks the pair as one call continued, not two.
* **`Kit`'s own line (every call, no exception):** `Kit` cannot see its own spend, so the main session (`Intent`) holds the call's `<usage>` and writes the `Kit` line into the card's `## History` right after `Kit` returns — the same skeleton and the same `unknown` rules. A card that passed through `Kit` and has no `Kit` line is a skipped step to be written from the call's transcript, not a figure that was unknown.
* **Plumb line (`AGENTS.md` §6):** the `plumb-haiku` call returns `<usage>` like any `Agent` call; the line is written by `Spec` (or the main session that ran the call for it) with `node .claude/scripts/claude-economy.cjs line --node Plumb --agent-id <agent_id> --tokens <subagent_tokens> --duration-ms <duration_ms> --desc "role <name>, N % (gap G, clarity C), <executor>, <outcome>"`. An external executor adds its own-unit segment before the dash (`ECONOMY.md`, "External model and external service").
