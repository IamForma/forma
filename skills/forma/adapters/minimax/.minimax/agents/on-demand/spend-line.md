# Spend line — MiniMax Code

**Write the line exactly to `AGENTS.md` §3's template, every field present in order — `attempt,` as its own word, never a bare number in its place; the dash before the engine tag.** A line that drops a word or reshapes the punctuation still reads to a human, but `tally.cjs` and `check-board.cjs` parse it by that exact shape — a malformed line is invisible to both and the card can reach `done` without either ever having checked it. Prefer the script's own output over hand-typing the line.

Read this file when you write a spend line into a card's `## History`: `Intent` after a node returns and before a card's commit; `Kit` or `Run` after an external-model call they made themselves. The contract itself — skeleton, fields, the `unknown` state, external model and service, `Intent`'s own lines — `.forma/manual/en/03-protocol/ECONOMY.md`; the law — `AGENTS.md` §3. This file holds what is true of MiniMax Code alone: where the numbers come from, and which script writes the line.

* **The line is derived, not typed.** The raw record of a call lives in this engine's journal — `.minimax/.ledger/calls.jsonl` — and the line is produced from it by the shared formatter `.forma/dashboard/spend-line.cjs` through this engine's adapter:
  `node .minimax/scripts/sync-ledger.cjs --derive '<record>' <Node> "<what was done>"`
  The record is one JSON object: `{"timestamp": "...", "conversationId": "<task id>", "input_tokens": N, "output_tokens": N, "cache_read_tokens": N, "duration_s": N}`. The call id of the law is the child's **`task_id`** from the return of the call — the same id `task_append` continues a live call with. Engine tag: `minimax:`.

* **What the numbers are, and what they are not.** The numbers are **established**: they are read from the call's own transcript — the runtime writes a per-step `usage: {input, output, cacheRead, cacheWrite}` and the model name into the session's `messages.jsonl`, and the session's directory name is the base64 of its `sessionId`, so the transcript is found by the very identifier the call returned. The record carries them; the derived line is exact. **A number you did not read is never written:** if the transcript cannot be found, the derived line carries `unknown tokens (cache-read unknown)` and the reason. `unknown` with a reason is what the contract asks for, and the core's `engine-tag` check exists precisely to catch a zero or a guess.

* **N is the whole call, cache included.** The canonical form of the line: `N = tokens_in + cache_write + cache_read + tokens_out`, and the work is `N − R` (`ECONOMY.md`, "Canonical variables"). A line that writes N *without* the cache is read by the core as "N was recorded without the cache" and gets R added — but only when `R > N`; with `R ≤ N` the total and the work would both be understated. Derive the line with the script; do not add the cache to N by hand.

* **The journal is written by the platform.** A record is appended by the package's `SubagentStop` hook — the platform's own capture of the call, with the platform's identifier. `node .minimax/scripts/sync-ledger.cjs --append '<record>'` remains for the rare case when the node itself made a call the hook could not see. The core's parity check `.forma/board/checks/ledger-parity.cjs` finds the journal by convention (`.minimax/.ledger/calls.jsonl`) and compares it with the card: every record must have exactly one line in the card, and every line exactly one record.

* **Continuation line (`AGENTS.md` §2, `kit.md` "Return"):** a continuation of the same live call (`task_append` on a `task_id`) is one call, not two — the same `task_id` appears in both lines, and `continuation` is named in the description so the ledger can tell the pair from a reassembly: `` `Kit`, YYYY-MM-DD: attempt (continuation), N tokens (R cache-read), T s, `<task_id>` — minimax: <correction sent, one sentence>. ``

* **What does not apply to this engine.** The Claude-side economy scripts (`claude-economy.cjs`, `card-session-spend.cjs`, `session-economy.cjs`) read Claude's own transcripts and say nothing about this engine's calls; do not cite them. The per-card and per-dialog ledgers of the main session are read by the core's dashboard from the engine's own journal; until the platform capture exists, the main session's own lines are written from the same journal.

* **Plumb line (`AGENTS.md` §6):** the Plumb call returns like any other call; the line is written by `Spec` (or by the main session that ran the call for it) with the same `--derive` call, the description naming the role, the reading, the executor and the outcome: `"role <name>, N % (gap G, clarity C), <executor>, <outcome>"`. An external executor adds its own-unit segment before the dash (`ECONOMY.md`, "External model and external service").
