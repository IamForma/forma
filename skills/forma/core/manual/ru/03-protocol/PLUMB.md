# Отвес (Plumb)

Мера между нарезкой и исполнением. Один язык для пяти узлов; не шестой узел. Закон — `AGENTS.md` §2 «The Plumb», запрет 17.

## Зачем

`Spec`, `Kit` и `Run` читают одну карточку на трёх диалектах. За разрыв платит `Run` (переделка) и `Kit` (проход комплектования на каждой карточке). Отвес читает карточку один раз против каталога ролей `Run` и называет, насколько они совпадают, — числом, а не мнением. Подходящая карточка идёт прямо в `Run`, а `Kit` вызывается только создать недостающую роль.

## Что отвечает

Модель решений: не пишет текст и ничего не объясняет. Три типизированных показания, смешиваются в одном вызове:

| Показание | Вопрос | Ответ |
|---|---|---|
| choice | какая роль ближе | роль, вероятность по каждой роли, уверенность |
| score | насколько ясно сформулирована задача | 0–4, уверенность |
| noul | берёт ли ведущая роль эту задачу | вероятность 0–1 |

## Кто решает

`Spec`, по порогам в `PROJECT.md` (вероятность лидера, разрыв до второй, noul, ясность — отдельно для каждого исполнителя). Отвес советует; он не подтверждает работу (запрет 1) и не заменяет проверку результата `Intent`.

| Показание | Куда |
|---|---|
| подходит | `Run`, роль записана в `## Снаряжение` (`why: plumb`) |
| ниже порога / малый разрыв | `Kit` — создаёт точную роль, проверяет тем же вызовом |
| низкая ясность | `Spec`, один раз — переформулировать, не дробить ради процента |

## Исполнители

Задаются `plumb` в `PROJECT.md`. По умолчанию — встроенная малая модель (`plumb-haiku`), ничего не выходит за семейство моделей. Рекомендуется внешняя модель решений за скриптом очистки. Нет ключа, ошибка или отказ очистки — откат на встроенную, причина в истории карточки.

**`jev` (Claude Code).** Драйвер `.forma/plumb/plumb-run.cjs` очищает задачу и каталог ролей (`--engine <id>` берёт `runRolesDir` адаптера этого движка, `--roles-dir <путь>` — папку; без аргументов — каталог Claude), затем вызывает Decisions API OpenRouter (`typesafe/jev-1.14`) через мост: типизированный запрос `questions`+`state`, не `chat/completions` — модель сразу отвечает `choice`/`score`/`noul`, одним вызовом. При отсутствии ключа, ошибке моста или отказе очистки печатает отметку отката вместо вызова Jev; вызывающий тогда запускает встроенный исполнитель и записывает эту попытку как его, с названной причиной — никогда как состоявшееся показание `jev`. Разовый переключатель `plumb-switch.cjs` меняет только слово-селектор `plumb` в `PROJECT.md`; останавливается без записи при отсутствии ключа и сам не ставит ни лимит вызовов на цикл, ни пороги для jev — оба задаёт человек.

## Очистка (запрет 17)

Скрипт, не модель, fail-closed: только пять полей `## Задача`; значения из `VARS/` и `.env` заменяются на имена; шаблоны (адреса, токены, номера, пути, IP) маскируются; домен сайта маскируется; остаток, похожий на секрет, — отправки нет. Персональные данные и секреты живут только в `VARS/` и `.env`, в карточке их нет.

## Как идёт карточка

1. `Spec` нарезает; у карточки пять полей `## Задача`.
2. Скрипт очистки собирает вход только из этих полей. Отказ → внутрисемейный исполнитель; остаток, похожий на секрет, → карточка к человеку.
3. Исполнитель читает очищенную задачу и каталог ролей (блок «берётся / не берётся» каждого профиля) и возвращает `choice`, `score`, `noul`.
4. `Spec` сверяет с порогами, записывает роль в `## Снаряжение` или оставляет пустым, а строку расхода вызова (с показанием) — в `## История`.
5. Подходит → `Run`. Ниже → `Kit` создаёт или правит роль и проверяет тем же вызовом. Низкая ясность → `Spec` переформулирует один раз.

## Замер исполнителя

Скрипт только готовит и считает; читает встроенный исполнитель самого движка, поэтому каждый движок замеряет свой.

1. `node .claude/scripts/plumb-measure.cjs prepare <outDir>` — очищенные задачи закрытых карточек (`batch.json`), каталог ролей (`catalog.md`), фактически применённые роли (`truth.json`).
2. Встроенный исполнитель движка получает `catalog.md` и `batch.json` одним пакетным вызовом и возвращает по каждой карточке `choice` (роль, вероятности, уверенность), `score` (ясность), `noul`. Сохраняется как `results.json` (`[{id, choice, score, noul}]`).
3. `node .claude/scripts/plumb-measure.cjs score <outDir> results.json --executor <имя>` — строгое совпадение, совпадение при уверенности ≥ 80, промахи.
4. Кто замерял, сообщает числа человеку; пороги исполнителя ставятся в `PROJECT.md` только по решению человека.

## Настройки (`PROJECT.md`, «Маршруты»)

| Настройка | Смысл |
|---|---|
| `plumb` | исполнитель: `haiku` (по умолчанию, внутри семейства) или `jev` (внешняя модель решений) |
| пороги | вероятность лидера, разрыв до второй, noul лидера, ясность — раздельно для каждого исполнителя; пересматривает `Core` только через остановку с докладом |
| внешняя модель | провайдер, модель, имя ключа в `.env`, маскируемый домен сайта, лимит вызовов за цикл (в вызовах, не в долларах) |

## Инструменты

| Инструмент | Что делает |
|---|---|
| `plumb-scrub.cjs` | очищает задачу карточки; `--site` добавляет маскируемые хосты; при отказе выходит с кодом 2; тест — `plumb-scrub.test.cjs` |
| `plumb-measure.cjs` | `prepare` собирает пакет из закрытых карточек (применённая роль — эталон), `score` сверяет ответы исполнителя с ним |
| `plumb-haiku` | встроенный исполнитель, субагент с одним инструментом `Read` |
| `.forma/plumb/plumb-run.cjs` | драйвер `jev` (общая зона): очистка задачи и каталога из `--roles-dir` / `runRolesDir` движка `--engine` (без аргументов — каталог Claude) → Decisions API OpenRouter (`typesafe/jev-1.14`) через мост → `{choice, score, noul}`, либо отметка отката при отсутствии ключа / ошибке моста / отказе очистки |
| `plumb-switch.cjs` | меняет селектор `plumb` в `PROJECT.md`; останавливается без записи при отсутствии ключа; не ставит ни лимит вызовов, ни пороги jev |

Исполнитель получает право решать сам только после замера на закрытых карточках: совпадение с применённой ролью и совпадение при пороговой уверенности записываются в `PROJECT.md`.

## Для `Core`

Каждое показание — строка в истории карточки. `Core` читает по строкам долю принятых с первой попытки: низкая ясность → `Spec`; роль названа уверенно, а укомплектовано иначе → `Kit`; роль подтверждена, но профиль не дотягивает → `Kit` правит профиль; пороги плывут → остановка с докладом. Цель — точность и меньше расхода на недопонимание между узлами: доля расхода на `Kit` должна падать при неизменной доле принятых с первой попытки.

**Отвес проверяет и на дубль, не только карточку.** Перед тем как `Kit` заведёт новую роль, он прогоняет форму задачи (строку «берёт» и 1–2 примера) тем же вызовом против каталога: уверенность не ниже порога исполнителя на существующей роли — та роль расширяется, а не дублируется; ниже порога — новая роль с явной строкой «не берёт», называющей ближайшего соседа (`kit.md`, «Every assembly leaves the catalog something»). Поэтому же `Kit` теперь заводит недостающую роль тем же вызовом, не открывая отдельную карточку на оснастку и не заставляя задачу ждать.

**Вторая метрика: доля карточек через `Kit`.** `node .forma/dashboard/tally.cjs .devtool/features` → `byNode.Kit.files` (карточки с хотя бы одним заходом `Kit`) к `cardsWithAttempt` (все карточки с любым записанным заходом). Доля должна падать по мере роста каталога — её рост при неизменном каталоге говорит о том, что проверку на дубль пропускают, а не о том, что выросла сама работа.
