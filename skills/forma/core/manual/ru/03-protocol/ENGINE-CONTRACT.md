# Контракт движка (ENGINE-CONTRACT)

Спецификация определяет контракт взаимодействия между общим ядром протокола Форма и адаптером конкретного движка (`.claude/`, `.agents/`, `.codex/` и др.).
Каждый движок в своём разделе §8 обязан явно объявить по каждому из девяти контрактов: выполняется ли он **конструктивно** (платформой, хуками, независимым журналом) либо держится на **дисциплине** (удерживается осознанностью узла, если механизм платформы физически недоступен).

---

## Девять контрактов движка

### 1. Корневые правила (`root-rules`)
- **Что гарантирует:** Разделы 1–7 `AGENTS.md` являются единственным источником закона. Адаптер движка не дублирует §§1–7 в своих файлах.
- **Чем доказывается:** Нативный импорт (`@AGENTS.md`) или нативное чтение; проверяется командой `node .claude/scripts/sync-engines.cjs --check`.

### 2. Изоляция узлов (`isolation`)
- **Что гарантирует:** Физическое разделение контекстов между `Intent`, `Spec`, `Kit`, `Run` и `Core` во исполнение запретов 1 (независимое подтверждение) и 7 (чистый контекст). По умолчанию все задачи по нарезке, оснастке и коду делегируются изолированным субагентам (при необходимости параллельно), пока человек явно не скомандует «Действуй сам».
- **Чем доказывается:** Режим Mode 2 (выполнение через изолированные субагенты в отдельных беседах) с гейтом в `new-card.cjs`, запрещающим открытие производственных карточек в деградированном режиме Mode 1; фиксируется в `.state/capabilities.json`.

### 3. Доставка роли главной сессии (`role-delivery`)
- **Что гарантирует:** Главная сессия работает как `Intent` и получает файлы `intent.md` и `intent-session-start.md` до первого ответа человеку.
- **Чем доказывается:** Внедрение через сессионные хуки (`SessionStart`, `PreInvocation` со структурированным `injectSteps`) либо явное объявление дисциплиной в §8 с результатами решающего эксперимента.

### 4. Продолжение вызова (`call-continuation`)
- **Что гарантирует:** Локальные помарки одного и того же вызова `Run` исправляются отправкой письменного уточнения по живому `conversationId` (`send_message`) без истории, а не пересборкой.
- **Чем доказывается:** Механизм отправки сообщений живому вызову; проверка статуса (`manage_subagents list`) и обязательный переход к пересборке (вариант B) при недоступности вызова.

### 5. Строка расхода (§3, `spend-line`)
- **Что гарантирует:** Каждая строка захода в `## История` несёт токены, длительность, cache-read и id вызова, считанные напрямую из результата вызова платформы, а не из памяти узла.
- **Чем доказывается:** Сырой журнал вызовов (`calls.jsonl`), наполняемый хуком `PostInvocation`, форматирование общим модулем `spend-line.cjs`, проверка взаимного паритета 1:1 скриптом `ledger-parity.cjs`.

### 6. Охрана удалений (§2, запрет 1, `deletion-guard`)
- **Что гарантирует:** Уничтожение или перемещение охраняемых файлов протокола (`.claude/`, `.agents/`, `.codex/`, `.devtool/`, `.forma/`, `AGENTS.md`, `PROJECT.md`, `GOAL.md`) блокируется платформой. Разовая разблокировка возможна только по парольной фразе человека «Отключи сенсорику».
- **Чем доказывается:** Хук `PreToolUse`, запускающий кроссплатформенный модуль `guard-delete.cjs` по реестру `protected-paths.json`; проверяется тестом `test-guard-delete.cjs`.

### 7. Протокол доски (§6–7, `board-protocol`)
- **Что гарантирует:** Карточки строго соблюдают пять обязательных полей, виды (`дело`/`оснастка`/`решение`), синхронизацию `status` и `assignee`, и строки этапов `stage` и причин `why` в `## История`.
- **Чем доказывается:** Проверяется на каждой карточке валидатором `node .forma/board/check-board.cjs <card>`.

### 8. Отвес Plumb (§2, `plumb`)
- **Что гарантирует:** Независимое измерение нарезки по каталогу ролей с возвратом строгого JSON `{choice, score, noul}` и обязательной очисткой секретов (fail-closed).
- **Чем доказывается:** Встроенный исполнитель на малой модели либо внешний исполнитель (`typesafe/jev-1.13`) через движко-независимый драйвер `plumb-run.cjs`.

### 9. Префлайт и верификация установки (`preflight`)
- **Что гарантирует:** Проводка адаптера движка (хуки, роли, права, возможности) проверяется при установке и обновлении.
- **Чем доказывается:** Запись в `.forma/install-manifest.json`, профиль верификации `verify-profile.cjs` и запуск проверки `node .forma/verify/verify-install.cjs`.
