# Пять зон протокола «Форма» — конструктор

Фиксировано — сам принцип пяти узлов и правила маршрута (`AGENTS.md`). Не фиксировано — конкретный инструмент под каждым узлом: доска, дашборд, канал интервью, профиль проекта — это сменные детали конструктора, не единственно возможная реализация. То, что описано ниже как «наш выбор» — референсная реализация, сделанная максимально хорошо, но не единственная законная. Человек волен собрать свой дашборд, свой граф, свой профиль проекта, свой канал интервью — принцип пяти узлов от этого не меняется.

Нумерация зон — не порядок маршрута исполнения (`Intent → Spec → Kit → Run → Core`), а порядок зависимости установки: от механики — к общению — к субстрату — к аналитике поверх субстрата — к исполнению.

---

## 1 · Kit — ядро (механика)

**Что входит:** закон протокола одним файлом (`AGENTS.md`) и обёртки движков с их §8 (`.claude/rules/claude-8.md`/`.agents/rules/gemini-8.md`) + ролевой функционал пяти узлов (`.claude/agents/`, `.agents/plugins/forma/agents/`) — сама механика: порядки, процессы, последовательности, производственные взаимосвязи (кто от чего зависит, как передаётся работа).

**Обязательно, часть ядра.** Без этого нет вообще ничего — это то, из чего сделаны все пять узлов. Правит эту схему физически `Intent` (`intent-housekeeping.md`) — но по природе, по сути снаряжения, это территория `Kit`: сама схема есть описание того, как снаряжать.

**Устанавливается:** ядро `forma` (`claude plugin install forma@forma`).

## 2 · Intent — общение с человеком (интервью)

**Что входит:** намерение, разговор, интервью — получить от человека максимально точную информацию. Это ключевая задача протокола: любая неточность на этом шаге размножается по всему циклу.

**По умолчанию:** классический канал — харнесс, `AskUserQuestion`/чат, уже встроенная в среду (Claude Code, Codex и т.п.) возможность вести интервью с человеком.

**Улучшение поверх — часть ядра, не компаньон.** Визуализация интервью (`forma-grill-with-ui`, карточки вопросов, обсуждение по каждому, итоговый документ по пяти осям Формы) ставится тем же вызовом `forma`, вместе с базовым терминальным вариантом; `Intent` выбирает между ними сама — браузер по умолчанию, когда доступен.

## 3 · Core — канбан-доска

**Что входит:** физическая доска (`.devtool/features/`) — единственное место, куда стекается всё: статус карточек, история, результат, статистика расхода, накопленный опыт и знания.

**Обязательно, но отдельно от ядра.** Без доски не работает не «зона Core» в узком смысле — рушится субстрат, на котором стоят все пять узлов разом: дашборду и графу неоткуда брать данные, `Intent` не может сверить критерий, `Kit` не может снарядить по фактам. Именно поэтому здесь выносится и итоговый вердикт цикла — Core судит по тому же субстрату, из которого читают остальные.

**Не переносится плагином `forma`.** Ставится отдельно — расширение VS Code [Kanban Markdown](https://marketplace.visualstudio.com/items?itemName=LachyFS.kanban-markdown) (`code --install-extension LachyFS.kanban-markdown`), сегодня наш единственный выбор технологии для этой обязательной функции. Сам принцип (централизованная точка сбора статусов/истории) фиксирован; конкретная технология — сменная деталь, как и всё остальное в этом списке, кроме пункта 1.

## 4 · Spec — граф и дашборд

**Что входит:** аналитика поверх доски. `Spec`, нарезая цели на карточки, порождает материал, который дашборд показывает в реальном времени (расход по узлам, оснастка, статус), а граф знаний со временем сворачивает в переиспользуемое знание (`.devtool/features/done/`, граф «Опыт»).

**Дашборд + граф в одной вкладке интерфейса — часть ядра, не компаньон.** Ставится тем же вызовом `forma`. Триггер пересборки графа и исполнитель (внешняя модель/субагент/вручную) настраиваются вместе с человеком при установке, не решаются за него.

**Конструктор:** человек может собрать свой дашборд и свой граф по-своему — наш вариант референсный, не единственный.

## 5 · Run — профили проектов

**Что входит:** снаряжение исполнителя конкретными инструментами дела — то, чем реально пользуется `Run`, когда делает работу в конкретном проекте (сайт, приложение, что угодно ещё).

**Два состояния, оба уже существуют:**
- **Пустой профиль** — каркас `project/` (шесть файлов, шесть каталогов), заполняется вместе с человеком через интервью (`project/config/SETUP.md`), часть ядра по умолчанию.
- **Заранее подготовленный профиль** — под конкретный тип проекта уже готовы каталоги, документация, рекомендуемые скиллы. Пример: `forma-wordpress-novamira` (Novamira MCP, Magnific, скиллы `novamira-wp-deploy`/`novamira-wp-elementor`/`excalidraw-diagrams`).

**Конструктор:** каждый человек может создавать свои собственные профили под свой тип задач — `forma-wordpress-novamira` не единственно возможный профиль, а один из многих, которые можно завести.

## Сводная таблица

| № | Узел | Зона | Статус | Артефакт |
|---|---|---|---|---|
| 1 | `Kit` | механика (схема, роли) | обязательно, ядро | плагин `forma` |
| 2 | `Intent` | общение с человеком (интервью) | обязательно, ядро | плагин `forma` (терминал + браузер) |

| 5 | `Run` | профиль проекта | база встроена (пустой каркас); альтернатива — по выбору | `forma-wordpress-novamira` (и другие, по типу проекта) |

**Правило регистрации:** новая зона или отделяемый шаблон — новая строка в этой таблице и свой раздел выше, в тот же заход, которым он создан. Подробности — `.forma/manual/ru/03-forma/SKILLS.md`.
