# Экономический контракт

Один контракт для всех движков. Ядро считает; адаптер движка только достаёт. Математика — `.forma/dashboard/economy.cjs`; тест соответствия — `node .forma/dashboard/economy.test.cjs`.

## Канонические переменные

| Переменная | Смысл | Единица | Обязательность | `unknown` |
|---|---|---|---|---|
| `tokens_in` | некэшированный вход вызова | токены | по вызову, стенограмма | — |
| `tokens_out` | выход модели | токены | по вызову, стенограмма | — |
| `cache_read` | вход, прочитанный из кэша (R) | токены | да, в строке карточки | `(cache-read unknown)` |
| `cache_write` | вход, записанный в кэш | токены | по вызову, стенограмма | — |
| `duration_s` | длительность вызова (T) | целые секунды | да, в строке карточки | `unknown s` |
| `turns` | число оборотов (раундов) за вызов | штуки | нет | — |
| `call_id` | id одного вызова; для работы в основной сессии — id сессии | строка | да, в строке карточки | `` `id unknown` `` |
| `tool_uses` | обращения к инструментам за вызов | штуки | нет | — |
| `ext_units` | платный внешний сервис, в своей единице | `N <unit> (service/operation)` | когда был | — |

Строка карточки пишет итог **N = tokens_in + cache_write + cache_read + tokens_out**; работа = N − R. Разбивка по вызову живёт в стенограмме, не в карточке.

## Три состояния поля

- число — записано;
- маркер `unknown` — движок не вернул, узел это назвал: считается **отдельно**, никогда не 0;
- поля нет — строка старше правила: не считается никак.

## Скелет строки (`## История` карточки, `AGENTS.md` §3)

`` `Node`, YYYY-MM-DD: attempt, N tokens (R cache-read), T s[, K turns][, $X (provider/model)][, N <unit> (service/op)], `<call_id>` — <движок>: <что сделано>. ``

Тег движка после тире — ключ разбивки. Токены разных тегов не складываются; движки сравниваются только по общим полям — попытки, время, принятые карточки.

## Кто пишет строку и где

- **Кто:** вызывающий, сразу после возврата — не сам узел и не потом. **Где:** `## История` карточки.
- **Расход считается по факту, а не на глаз.** Узел не знает своего расхода изнутри — это знание лежит в метаданных вызова, не в его контексте. **Имена полей:** какое поле возврата движка какую переменную скелета заполняет — §8 файла движка; читается, не оценивается.

## Ключевая часть — по-английски; описание открывает движок

- **Язык.** Ключевая часть — всё до тире: `attempt`, `tokens`, `cache-read`, `s`, маркеры, сегменты внешней модели и внешнего сервиса — пишется **по-английски, в каждом проекте, на каком бы языке он ни шёл**; описание после тире — на языке карточки (`AGENTS.md` §6). Ключевую часть разбирают счётчики: одна кодировка держит их чтение одинаковым во всех проектах. Строки, написанные раньше на другом языке, остаются как есть (запрет 5) и по-прежнему читаются; новая, написанная так, называется в `sync-engines --check`.
- **Движок.** Описание после тире **открывается движком, который сделал работу** — `claude-code:`, `codex:`, `gemini:` — чтобы по карточке было видно, кто её исполнил и кто оставил расход незаписанным.

## T, R, K и id вызова

- **T:** длительность вызова в целых секундах.
- **R:** счётчик кэш-чтения вызова, прочитанный прямо из его собственного результата, без отдельного вызова. R почти всегда — постоянные накладные (загрузка этих правил и роли), а не сама работа; глубже он не делится, потому что ничто внутри одного вызова не отделяет содержимое карточки от собственно работы без добавления ещё одного вызова.
- **K:** число оборотов (раундов) за вызов — опционально. Пишется, только если вызов или его стенограмма это число фиксируют. Карточки без данных об оборотах не считаются в среднем и выводят `—` (не 0).
- **Id вызова:** идентификатор именно этого вызова, прочитанный прямо из его результата, как и числа рядом, — не составляется и не угадывается. Какое поле возврата его несёт — названо в §8 файла движка, как и все остальные поля расхода. Он стоит **последним в блоке расхода, вплотную перед тире**, после сегмента внешней модели или внешнего сервиса, если они есть: числа остаются там, где глаз их уже ищет, а непрозрачный токен — там, где глаз проскальзывает в прозу. **Отдельного вызова нет — id сессии:** работа внутри общей сессии берёт числа и id из транскрипта сессии этого движка (см. ниже «`Intent` в общей сессии»).

## Маркер `unknown`

Движок число не вернул вовсе: строка всё равно пишется целиком, с **маркером на месте поля** — `(cache-read unknown)` вместо `(R cache-read)`, `` `id unknown` `` вместо идентификатора. Два условия, оба обязательны: маркер ставится **только после попытки взять число из транскрипта самого вызова** (как читать — названо в §8 файла движка, рядом с самими полями расхода), и **причина названа в прозе после тире**. Маркер — не право пропустить чтение и никогда не замена числу, которое вызов вернул.

**Что движок так и не вернул, пишется фактом, а не оставляется дырой.** Оценка на глаз запрещена, а строка не по форме молча выпадает из суммы: маркер оставляет строку законной, а пробел — **посчитанным отдельно**, отдельной величиной («unknown: N заходов»), никогда не нулём.

## Внешняя модель и внешний сервис

- **Внешняя модель.** Вызывающий узел пишет свою строку и вставляет `$X.XXXXXX (provider/model)` перед тире. Единственное исключение из «пишет вызывающий»; запрет 1 оно не нарушает. Механика — `run-external-model.md`, `kit-graphs.md`.
- **Внешний сервис.** Платный сервис, доступный через MCP или API — генерация изображений, 3D, речь, — тарифицируется **в своей единице**, не в токенах и не в долларах. Узел вставляет `N <unit> (service/operation)` перед тире, по одному сегменту на каждый затронутый сервис: `` 1160 credits (image-service/upscale) ``. Число читается из собственного ответа вызова, как любой другой расход, — не оценивается по прайсу. Какие сервисы подключены, в какой единице каждый тарифицируется и откуда читается его число — `PROJECT.md`, «Внешние сервисы».

## `Intent` в общей сессии

Работа, которую `Intent` делает внутри общей сессии, — сам исполняет карточку, проверяет, оркестрирует узлы, — считается **по транскрипту основной сессии движка** и пишется в карточку обычной строкой расхода: N, R и T читает скрипт движка (§8), вместо id вызова — id сессии, ответы субагентов исключены (они уже в `## История`). Каждый ответ принадлежит одной карточке. Пишет тот движок, что сделал работу, до коммита карточки. **`0 tokens` — исключение, не умолчание:** допустимо, только когда транскрипт не прочитался или в нём ничего нет по карточке, и пишется с маркерами из «Маркер `unknown`» (`unknown tokens (cache-read unknown)`, `` `id unknown` ``) и причиной после тире. Событие, не являющееся работой — одобрение человека, смена статуса, — это строка события без `attempt` (`AGENTS.md` §6). Вызванный как субагент — строку пишет вызывающий на общих условиях. Статья **«`Intent` ↔ человек»** остаётся журналом всего диалога и пересекается с этими строками; маршруты сравниваются по строкам карточек, никогда не сложением двух.

## Что требуют проверки

- **R и T не необязательны.** Строку без любого из них называет `sync-engines --check` (со дня, когда правило вошло в проект, `.forma/living/checks.json`; прежние строки остаются как есть, запрет 5). Метаданные вызова не переживают вызов, так что незаписанный расход не восстановить.
- **Id вызова сшивает карточку с журналом инструментов** — одно общее поле делает читаемым снаряжение по виду задачи. Проверяется только вперёд: требуется от строк позже дня, когда поле вошло в проект (`.forma/living/checks.json`), потому что id не переживает своего вызова.

## Обязанность адаптера

§8 каждого движка — или указанный в нём on-demand-файл — называет, какое поле его возврата в какую переменную идёт и как читается R. Его строка проходит тест соответствия.
