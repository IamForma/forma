# Скиллы и плагины

Реестр всего, что связано с протоколом «Форма» — по одному разделу на каждый плагин маркетплейса `IamForma/forma` (`.forma/protocol/.claude-plugin/marketplace.json`), плюс канбан-доска, которая плагином не является. Ядро (`forma`) приносит всё, без чего протокол не работает, одним вызовом. Отделяемых осталось два: шаблон проекта (плагин, выбор человека) и канбан-доска (внешнее расширение редактора, обязательное условие).

**Правило:** новый плагин в маркетплейсе — новый раздел здесь, в тот же заход, которым плагин зарегистрирован. Заносит тот, кто плагин создал.

---

## `forma` (ядро, обязательный)

Сам протокол — пять узлов (Intent/Spec/Kit/Run/Core), правила маршрута, карточки, пороги — **и всё, без чего он не работает: оба варианта интервью и дашборд с графом знаний.** Устанавливается один раз в проект как `AGENTS.md` (закон, §1–7) + `.claude/rules/claude-8.md` (§8 Claude Code) + `.claude/agents/` + `.claude/hooks/` (+ параллельно `.agents/rules/gemini-8.md` + `.agents/plugins/forma/` для Google Antigravity):

- **интервью** — терминальный скилл `grilling` и браузерная страница `forma-grill-with-ui` (форк [`jasonku09/grill-with-ui`](https://github.com/jasonku09/grill-with-ui), MIT, интерфейс на русском, доработан под наши форматы); `Intent` выбирает между ними сама — браузер по умолчанию, когда доступен, иначе терминал (`intent-goal-opening.md`, «Эпик»);
- **дашборд** — локальный интерфейс расхода/оснастки узлов (`node .forma/dashboard/serve.js` → `localhost:5050`, живое SSE-обновление при правке карточки) и граф знаний (`graphify`) одной вкладкой того же интерфейса, не отдельным окном. Несёт форкнутую копию стороннего скилла `graphify` (версия на момент форка `0.6.0`) — обновления апстрима подтягиваются вручную, только после проверки на комплектность и совместимость, а не автоматически. Пересборка графа настраивается в `.forma/dashboard/graphify.config.json`: `trigger.mode` (`off` по умолчанию, или `history-accumulation` по накоплению истории) и `executor.channel` (`internal` по умолчанию — через живую сессию, или `external` — через `.claude/scripts/external-model-bridge.cjs`, требует ключа в `.env` и денег).

Ничего доменного ядро не несёт — общие правила и общий инструмент, одни и те же для любого проекта на этой схеме.

Установка: `claude plugin install forma@forma` → скилл `forma` (`/forma`, или просто «поставь Форму» / «обнови Форму» словами).

Подробности — `.forma/protocol/skills/forma/SKILL.md`.

## `forma-wordpress-novamira`

Отделяемый шаблон проекта — разработка WordPress с помощью Novamira MCP (+ Elementor) с Aura/Magnific в комплекте. Два готовых скилла (`novamira-wp-deploy`, `novamira-wp-elementor`) + установщик пустой заготовки `project/config/SITE.md` (архитектурный снимок конкретного сайта — своя для каждого проекта, не переносится общей; продуктовые данные живут в `project/`, не в `.claude/skills/`). Отделяем, потому что шаблон предопределяет опыт работы — маршрут, который проект ещё только учится формировать и передавать; ядро от этого решения не зависит.

Установка: `claude plugin install forma-wordpress-novamira@forma`.

Подробности — `.forma/protocol/templates/forma-wordpress-novamira/README.md`.

## Канбан-доска (не плагин этого маркетплейса)

Обязательное внешнее условие, не рекомендация: без расширения VS Code Kanban Markdown (`code --install-extension LachyFS.kanban-markdown`) карточки `.devtool/features/` остаются просто папкой `.md`-файлов — дашборду, графу и сверке критериев неоткуда брать данные. Ставится вручную расширением редактора (VS Code или Antigravity), потому что иначе никак — ни один плагин Claude Code не может поставить расширение стороннего редактора. Подробности — `.forma/manual/ru/03-forma/ZONES.md`, зона 3 «Core — канбан-доска».
