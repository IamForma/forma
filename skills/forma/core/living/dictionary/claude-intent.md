# Словарь: `.claude/agents/intent.md`

Уровень 2. Английский оригинал — `.claude/agents/intent.md`. Gemini-зеркало — `.agents/plugins/forma/agents/intent.md` (`living/dictionary/gemini-intent.md`).

## Что это

Ролевой файл узла `Intent` — держателя образа результата. Единственный из пяти узлов схемы, у которого есть настоящая память между вызовами (ведёт интервью и сверку напрямую в общей сессии, не через изолированный вызов Agent tool). Читает его только `Intent` — и только на своих вызовах, не остальные четыре узла.

## Зачем это

`Intent` отвечает за два принципиально разных действия, которые легко перепутать: держать образ результата (требует непрерывной памяти — понимать, как менялось желание человека) и поштучно сверять каждую задачу с признаком готовности (требует нарочитой беспамятности — иначе четвёртая сверка идёт уже не по записанному признаку, а по впечатлению «обычно всё в порядке»). Файл прямо разводит эти два режима работы в первых же абзацах, чтобы не дать памяти незаметно просочиться туда, где она должна отсутствовать.

## Как это работает

Файл организован вокруг **редкости события**, а не вокруг важности:

- **«Каждая задача»** и **«Сверка вида»** — читаются на каждом обычном вызове: пятиэтапный протокол визуальной сверки (сначала машина, потом глаз; все расхождения разом; три поля на расхождение — что видно/что ожидалось/где; без предложения способа исправления; никаких «похоже»).
- **«Открытие цели»** и **«Хозяйство»** — редкие события (раз на цель / когда человек просит тронуть саму схему), поэтому вынесены в отдельные файлы уровня 2b (`.claude/agents/on-demand/intent-goal-opening.md` и `intent-housekeeping.md`) — `Intent` читает их только в момент самого события, не держит их вес на каждом обычном вызове. Это прямое применение принципа «вес файла соответствует частоте его чтения» (`manual/ru/03-forma/SCHEME.md`, §9).
- **«Закрытие круга»** — разделено на «Предъявление» (собрать и отдать `Core`, не судить самому) и «После вердикта» (записать журнал, разослать вызовы `Kit`/`Spec` на их сводки, спросить у человека подтверждение при достижении цели).
- **«Аварийный протокол»** — на случай, когда сайт не отвечает целиком и `Run` недоступен: единственный сценарий, где `Intent` действует напрямую, минуя `Kit`/`Run`, по трём жёстким правилам (сначала читать, потом чинить; реквизит только через `VARS/credentials.md`; правка только структурной способностью платформы).

Критерий приёмки узла — «красиво» (образ, который тянет к себе работу, не просто нравится) в паре с «справедливо» (образ должен быть достижим всей пятёркой, не только красив на вид одному `Intent`) — подробный разбор пары в `manual/ru/03-forma/PROTOCOL.md`, «Пять пар».
