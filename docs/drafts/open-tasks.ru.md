# Открытые задачи для других ИИ

Каждая задача самодостаточна: промт можно отдать другому агенту как есть. Общие правила для всех (вставлены в промты кратко):

- Репозиторий `IamForma/forma`, плагин «Форма» (протокол пяти узлов Intent/Spec/Kit/Run/Core). Ветку делать от `dev`, PR — в `dev`; `dev` → `main` вливает человек.
- Перед PR: `npm test`, `npm run lint`, `node scripts/check-release.cjs --traces`. Окончания строк — только LF.
- Платные прогоны живого агента (`test/eval-start-context.cjs`) **не запускать**.
- Если меняется поведение, версия поднимается в `.claude-plugin/plugin.json` и `package.json` (релиз выходит сам при смене версии).
- Тексты в «чистых зонах» (`skills/forma/**`, тесты) не должны содержать следов конкретного проекта: коды `card-NNN` кроме 001–009 и 099, `goal-NN` и т. п.

---

## 1. Нестабильный тест `checks-output`

**Суть.** `test/checks-output.test.cjs` («все порчи разом») дважды упал при полном параллельном прогоне и не воспроизвёлся в десяти повторах. Причина не найдена.

**Промт.**
> В репозитории IamForma/forma тест `test/checks-output.test.cjs` («все порчи разом: вывод доски и сверки, порядок находок») иногда падает при полном `npm test` и не падает отдельно. Найди причину: гонка при чтении stdout дочерних процессов, зависимость от порядка/времени, общий временный каталог, лимит буфера. Воспроизведи под нагрузкой (параллельные прогоны `node --test`, ограничение CPU), покажи падение, исправь причину, а не добавляй повторы. Не ослабляй проверку. Результат — PR в `dev` с описанием причины и доказательством, что падение воспроизводилось до правки и не воспроизводится после (не меньше 30 прогонов под нагрузкой).

## 3. Тяжёлый стартовый контекст

**Суть.** В каждую сессию входит ~56 КБ инструкций (`AGENTS.md` ~30 КБ, §8 ~4 КБ, Intent ~22 КБ) — 14–18 тыс. токенов до первого слова и снова после каждого сжатия.

**Промт.**
> В IamForma/forma сократи стартовый контекст, не меняя поведения протокола. Сначала измерь: `skills/forma/adapters/claude/scripts/instruction-weight.cjs` и размеры `skills/forma/core/AGENTS.md`, `skills/forma/adapters/claude/agents/intent.md`, `.../on-demand/intent-session-start.md`. Кандидаты на вынос «по требованию»: шаблон карточки и таблица видов работ из §6 `AGENTS.md`, детали роли Intent. Правила: закон §1–7 остаётся единым источником для трёх движков; вынесенное читается по событию (таблица «On-demand files» в `intent.md`); проверка `sync-engines --check` и все тесты зелёные; зеркало Gemini генерируется `sync-engines --apply` в установленном проекте (установи в временную папку с `--engines claude,codex,gemini`, скопируй `.agents/plugins/forma/agents/**` обратно); эталоны проверок перезаписываются `UPDATE_GOLDEN=1 npm test` только после осознанного просмотра diff. Результат — PR в `dev` с таблицей «было/стало» в байтах и токенах и списком вынесенных блоков с событием, по которому они читаются. Платные прогоны живого агента не запускать.

## 4. Пакетное создание карточек для Spec

**Суть.** `Spec` режет цель на карточки по одной: каждая — отдельный заход (`new-card.cjs`). Нужно создавать пачку одним вызовом, чтобы сократить число заходов.

**Промт.**
> В IamForma/forma скрипт `skills/forma/core/board/new-card.cjs` создаёт одну карточку на вызов. Добавь пакетный режим: `--batch <файл.json>` (массив объектов с теми же полями, что у флагов: kind, title, goal, route, over, after, delivers, criterion, budget, next, why, stage, demo), номера присваиваются подряд, зависимости `after` могут ссылаться на карточки того же пакета по индексу (`"after": ["#0"]`). Проверка доски (`check-board.cjs`) — один раз по всему пакету, ошибка по любой карточке — код выхода 1 и ни одного файла не записано. Обнови `skills/forma/adapters/claude/agents/spec.md` (и зеркало Gemini через `sync-engines --apply`), `tools:`-разрешения ролей (тест `test/roles-tools.test.cjs`) и добавь тесты по образцу `test/card-move.test.cjs`. Не меняй формат одиночного вызова.

Прочитай `skills/forma/core/manual/en/03-forma/ROUTES.md` и `LEVERS.md`. ## 8. Выбор `--compact off` не запоминается

**Суть.** Окно автосжатия: `off` не запоминается — при повторной установке с `--yes` снова ставится 250000.

**Промт.**
> В IamForma/forma (`bin/forma.cjs`, функции `chooseCompact`, `ownCompact`, `applyCompact`; тесты `test/installer-compact-bash.test.cjs`) выбор `--compact off` не запоминается: повторная установка с `--yes` ставит 250000. Запомни выбор в установленной описи (`.forma/install-manifest.json`, новое поле, формат описи не ломай — проверь `verify-install`) и учитывай его при `--yes`. Явный флаг `--compact <n>` перекрывает запомненное. Значение пользователя (переменная окружения, `~/.claude/settings.json`, `.claude/settings.local.json`) по-прежнему не трогается. Тесты на все ветки; обнови README.

**Суть.** Хук `guard-delete` работает по шаблонам команд; остаются скрипт-файл, который сам удаляет (`node clean.js`), и косвенные обходы (`cp -r` + `rm` по другим путям, `mv -t`).

**Промт.**
> В IamForma/forma (`skills/forma/adapters/claude/hooks/guard-delete.sh`, тест `test/hooks-guard-update.test.cjs`) закрой по возможности обходы `mv -t <каталог> <защищённый путь>` и `cp -r <защищённый путь> … && rm` и проверь, что обычные команды из списка PASS не блокируются. Если для скриптов-файлов (`node clean.js`) решение шаблонами невозможно — не имитируй его, а опиши предел защиты в `docs/drafts/plugin-overview.ru.md` и в сообщении хука. Тесты — оба режима (с `jq` и без).
